# Upgrade study and roadmap — 21 October 2026

**Base:** `main` at `5916726f8c085f2687ec756508914c5a713fa5bc`.
**Scope of the study:** the Rust workspace (core, store, runtime, server,
observe, CLI, testkit), the React dashboard, deployment and CI, and every
remaining Python file. Four parallel source surveys were followed by direct
reading of the hot paths named below. This document records what was found,
what the accompanying change set fixes, and an ordered roadmap for the rest.
It does not accept any work packet; see the [execution ledger](EXECUTION.md)
and [release status](../../operators/release-status.md) for acceptance.

The open Git Flow workspace PR (#167) owns `apps/dashboard/src/features/live-views/`
geometry, Git Flow and LiveViews files and adds `features/git-flow/`. This change
set does not modify those files.

## 1. Findings

### Correctness

| Finding | Evidence | Status |
| --- | --- | --- |
| The observer writes `status.json` up to 32 MiB, but every server reader capped the source at 8 MiB, so a valid snapshot over 8 MiB turned `/v1/legacy*` into 502s and marked the producer failed in views and Git health. | `observe/src/io.rs` (32 MiB) vs `server/src/legacy.rs`, `views.rs`, `operator_chat.rs` (8 MiB) | Fixed: one 32 MiB source bound; the 8 MiB SSE frame bound is unchanged. |
| History reads `token_yield.projects.<p>.credits_per_done_todo`, which the native observer never emitted, so `ty.p.<p>[3]` was always null. | `observe/src/history.rs` vs `usage.rs` `YieldTotal::value` | Fixed and tested; masked to null with other full totals when coverage is incomplete. |
| Disk `growth_gb_per_h`, `hours_to_full` and `rate_window_min` were hard-coded `null` after the Python retirement. | `observe/src/fleet.rs` `parse_disk` | Fixed: native estimate with the retired rules (20 min–3 h baseline, 12/24 h red/amber). |
| The observer only handled Ctrl-C; a supervisor's SIGTERM killed it mid-cycle. Files stayed safe (atomic writes) but the cycle was lost. | `observe/src/main.rs` | Fixed: SIGTERM finishes and publishes the current cycle. |
| Bearer tokens were compared with `!=`. | `server/src/lib.rs` `authorized`, `operator_chat.rs` `auth` | Fixed: constant-time comparison. |
| The server raises captain alerts for `unknown` Git health (shallow clones, unknown worktree state), which can be noisy for repositories that are always shallow. | `operator_chat.rs` `refresh`/`notify_health` | Not changed; recommend a per-project `alert_on_unknown` policy. |
| The server treats the producer as fresh for 90 s; the dashboard uses 180 s. | `operator_chat.rs` vs `features/live-views/feed.ts` | Not changed; the brief and Fleet health use three cycles (≥ 90 s). Recommend one shared constant. |

### Performance

| Hot path | Before | After |
| --- | --- | --- |
| Observer cycle | Fleet → projects → Git → health sequentially; previous `status.json` (≤ 32 MiB) parsed three times. | Git scans run concurrently with fleet/project collection; previous snapshot parsed once; per-stage timings published. In a one-project local smoke run the fleet lane (13–49 ms) ran inside the Git lane (110–123 ms) and the cycle took 114–134 ms; this is not a production measurement. |
| `/v1/legacy*` | Every request re-read, re-parsed, re-projected, re-serialized and re-gzipped up to 8 MiB (measured 1.68–1.84 s for complete detail in production). | Encoded projections cached per source revision (inode/size/mtime/ctime) and encoding; byte-identical hits; strong ETags and 304 revalidation. Repeat reads skip all CPU work. |
| Views hub (every 2 s) | Re-read and re-parsed the source and hashed it even when unchanged. | Skips both when the producer file and native cursor are unchanged. |
| Git health cache (every 5 s) | Parsed the full source to extract `git_health`. | Re-parses only a new source revision; freshness and notification retries still run every tick. |
| Dashboard polling | Detail (15 s), Git health (5 s) kept polling in background tabs; trend metrics and project details recomputed on every render. | Polls pause while hidden and resume on return; detail revalidates with `If-None-Match`; trends/projects memoized per snapshot. |

Not changed because the Store is integrator-owned (recommendations, in order of
expected impact):

1. `core/src/reducer.rs` clones the whole projection per event, making replay
   at startup, rebuild and backup O(N²). Apply events to a mutable projection.
2. `Writer::snapshot` deep-clones the projection on the single writer thread for
   every views tick, fleet request and SSE connect. Share an `Arc` snapshot
   rebuilt on change.
3. `events_after` is an N+1 query that re-hashes each row; fetch a page in one
   statement.
4. `/v*/fleet` returns every task without pagination.

### Logging and agent context

There was no structured logging: the daemon logged one startup line, the
observer one prose line per cycle, and no request was ever logged. Agents had
to read multi-megabyte JSON to learn whether anything needed judgment.

Now: a shared `agent_log` event format (logfmt default, NDJSON optional) with a
rollup that counts identical consecutive events instead of repeating them; one
observer event per changed cycle; a problem-request access log; and a
token-budgeted, deterministic fleet brief (`admiralty brief`, `/v1/brief`,
Fleet health). See [agent brief and compact logs](../../operators/agent-brief.md).

### Deployment

There were no service definitions, no activation or rollback command and only
`/healthz` (liveness). Production ran from hand-copied directories; the
documented `/srv/admiralty` layout did not match. `pnpm live` required Python.

Now: `packaging/systemd/` user units that run only from `ROOT/current`,
`admiralty release activate|rollback|status` (atomic links, never service
control), `/readyz` (feed freshness and assets), `admiralty state init`, and the
Rust `admiralty release evidence` preflight. See
[clean deployment](../../operators/deployment-systemd.md). The actual production
cutover remains the assigned deployment owner's decision.

## 4. Git health next steps

- **Ref moves:** compare refs with the previous snapshot to report non-fast-forward
  updates within the loaded window (a fact about the graph, not a claim of lost
  work).
- **Remote freshness:** `FETCH_HEAD` mtime per repository, so stale remote refs
  are visible before comparing against them.
- **Hygiene rates:** revert commits, merge ratio and trailer coverage on the
  integration first-parent chain (subjects and parents are already loaded).
- **Stashes and untracked bytes:** counts are cheap; sizes need a bounded walk.
- **Policy:** optional thresholds that turn metrics such as unmerged tips older
  than 30 days into `attention`, defaulting to off so existing alerts do not change.

## 5. Design follow-ups

  SVG node per history row per series.
- Add `aria-controls`/tabpanel and arrow-key navigation to the project tabs.

See the pull request for exact commands, counts and environment. Rust tests,
strict Clippy, formatting, contract checks, dashboard unit tests, typechecks,
production build and the full browser/axe suite (including the new Fleet health
journey against the real `admiraltyd`) were run locally on Linux as root with
Chrome for Testing 155.0.8059.84 and Node 24.22.0. Two pre-existing tests are

deployment, launchd units and clean-machine installation were not exercised.
