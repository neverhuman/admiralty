# Release scope and remaining gates

This page describes the native release boundary. The [execution ledger](../plans/admiralty-v2/EXECUTION.md) owns exact source revisions, failed and passing evidence, deployment observations and packet acceptance. It takes precedence over a component count or an agent's final message.

## Available and demonstrated

- Rust serves the HTTP API, React assets and optional old-port redirect. The detailed console retains its real producer data, project tabs, hierarchy, model badges and thirteen temporal plots.
- The [dashboard source qualification](../../receipts/integration/live-trends-display-20261020.json) verifies partial observed cost/token/yield series, missing hygiene diagnostics, original audit clocks and at most two display decimals. Full aggregates remain unknown when coverage is incomplete. The fixed Luna medium development launcher has mock-provider tests; it does not qualify native managed model admission.
- Protected native startup enables operator task intake, pending cancellation, unstarted contract revision and exact scoped agent context/inbox operations. It does not install provider-execution or candidate-acceptance authority.
- Opt-in [native agent routes](native-coordination.md) support authenticated typed sends and separately granted own-inbox application receipts through CLI/MCP. Synthetic HTTP/reopen qualification is separate from actual supervisor adoption; it does not establish complete production dogfooding.
- One actual production Admiral–captain–Admiral communication cycle is now verified at source5512531: distinct role sessions read/applied their messages and separately acknowledged events8–11. The [sanitized receipt](../../receipts/integration/native-actual-role-cycle-20261019.json) retains evidence hashes. Bootstrap wake-up still uses the legacy inbox; event-driven wake-up and general managed coding execution remain open.
- Durable task/message state, full-task CAS, exact retries, offline workplan registration, model policy proposals, backups, verification, restore rehearsal and explicit release staging are implemented components.
- The community candidate exports 28 public schema/TypeScript/runtime-validation roots through the same source generator. The original 23 schema files remain byte-identical; the additional attempt, execution and interface models retain their actual version 1 wire format. Runtime shape validation remains separate from domain checks and authority.
- The [latest current-host bundle receipt](../../receipts/integration/community-release-startup-20261020.json) records a rebuilt 73-file macOS arm64 release-profile payload at `d1659f4`: CLI, daemon, observer, all 28 schemas, complete guards, fresh production dashboard and license. Stage/archive/private install, repeat-archive equality, installed inspection/demo, tamper/no-overwrite refusal and clean shutdown with both SSE families held open pass. The [earlier candidate](../../receipts/integration/community-release-candidate-20261020.json) remains source-bound history. This is not clean-machine, Linux distribution or publisher qualification.
- The scoped `NativeTaskLoop` joins atomic admission, exact-key outbox dispatch, the actual observed-start sink and acknowledged closed-result transfer. Durable role renders and recipient baseline CAS now survive replay, reopen, rebuild and backup. These are composed components; production provider authority and authenticated context delivery remain separate.
- A real Linux deterministic integration at `eb62f5f635bea46e98c76e91499b56b4c7673849` exercised actual admission, observed resource enforcement and service closure, executed positive and negative checks, verified artifact custody, trusted acceptance and replay. See its [sanitized receipt](../../receipts/integration/eb62f5f635bea46e98c76e91499b56b4c7673849.json).

The demonstrated workload was a deterministic native computation. It did not invoke a coding provider or establish autonomous project delivery. Its fixed inherited CPU restriction does not qualify arbitrary per-service CPU assignment or exclusive fleet reservations.

The earlier `eb62` probe used exit17 for its wrong-oracle check and for other checker errors. Its negative control therefore does not independently distinguish an oracle mismatch from an infrastructure failure. Preserve that receipt with this limitation. The new task-loop probe requires a distinct typed mismatch exit23 after successful compilation, execution and complete capture; component tests do not substitute for its actual Linux result.

The [P03 source audit](../../receipts/integration/p03-source-gap-audit-20261020.json)
identified six concrete storage gaps: live writer/transaction telemetry, honest
WAL checkpoint reporting, indexed filtered task pages, canonical migration-family
tracking, backup schema/version binding and the complete abrupt-crash matrix.
These require implementation and tests; provider activation is not their blocker.
The [current startup repair](../../receipts/integration/atomic-store-startup-20261020.json)
groups schema initialization, recovery generation, replay and startup validation
in one Immediate transaction while preserving WAL/FULL/FK. The local Linux
fresh-Store probe measures about0.11s versus2.76–3.17s previously; sync calls
including orderly drop fall from19 to9. Two samples per source are scoped
measurements, not production page-load or tail-latency guarantees. Late-schema
and replay failures roll back new objects and preserve existing history. These
source improvements do not close the remaining P03 criteria.

Production startup currently leaves general native execution unqualified. A request cannot override that boundary or install a new authority. Provider identity remains unknown unless independently observed; requested names are not observations. Credentials, private configuration, runtime data and transcripts remain outside Git.

Run the [complete local CI command](local-ci.md) before pushing qualification
repairs. The [earlier source-bound full-matrix receipt](../../receipts/integration/local-ci-20261019.json)
remains historical evidence for its recorded revision. Later candidates require
their own exact-source logs and check results. Scoped source tests, private bundle
installation and local journeys do not establish a full managed release.
