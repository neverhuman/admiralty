## Prioritized findings

### R1 — P1: bind launch construction and qualification to admitted immutable inputs

**Location:** `crates/admiralty-runtime/src/providers/claude.rs:27-36`, `:48-79`, `:285-290`.

`ClaudeLaunch` contains free-form paths/model/budget/session data and can validate nonexistent, unowned paths; it has no contract/project/root/task/revision, attempt, registry model digest, node/help observation, custody/resource/lease/auth reference, context epoch or immutable launch/input digest. `qualification()` nevertheless returns `configuration_bound=true`, `launch_input_resume=true` and `parent_child_usage_deduplicated=true` without receiving any evidence. The parser also accepts version 99, a foreign model and bypassPermissions while this function still advertises the 2.1.302 canary. This is an integration blocker for P21's “actual configuration binding” and “same core invariants” criteria.

The exact-base first adapter already supplies a useful comparison: `providers/codex.rs:135-205` creates a private evidence-bound CLI observation; `:212-256` records admitted scope/resources/model/config; `:290-400` checks contract/digest/node/attempt/expiry and bounds the encoded prompt before constructing a shared session LaunchSpec. Its native execution qualification remains false. Introduce an equivalent prepared Claude launch using the shared launch envelope and explicit admitted inputs; derive supported capability observations from actual validated version/config/receipt evidence, with unsupported/unknown as the default.

The new module is currently unregistered and parsing is explicitly observational. This finding does **not** assert that current main runtime grants execution through this candidate; it says these booleans and builder cannot qualify that future admission.

### R2 — P1: require one bound init and an ordered, complete terminal turn

**Location:** `crates/admiralty-runtime/src/providers/claude.rs:220-227`, `:237-253`.

Expected-resume checking occurs only when an optional system/init event happens. A result-only stream with `session_id="foreign"` and usage is accepted with `expected_resume=Some("expected")`; the returned session is None. After a matching init, a foreign result session is also ignored. Repeated result events replace earlier errors, permission denials and usage; an assistant-only stream without a final newline is accepted even though the API documents a complete stream. An observed unsupported CLI version is merely copied into the output.

Bind the parser to the prepared launch/session/version/config; require exactly one valid init, validate session ownership on applicable subsequent frames, distinguish complete/failed/unknown lifecycle, reject conflicting/reordered terminal events, and retain producer EOF/process/capture-watermark evidence. Preserve replay identity/ordinals rather than overwriting state. Compare `codex.rs:739-747,772-807,855-875,1183-1249`, which already binds launch digests, offsets, lifecycle and capture completion. This adapter currently has no replay-safe event identity or watermark interface.

### R3 — P1: reject duplicate fields before converting JSON into Value

**Location:** `crates/admiralty-runtime/src/providers/claude.rs:211`.

`serde_json::Value` silently takes the last duplicate key. One result object containing `is_error:true,is_error:false`, two permission_denials keys, and nested `output_tokens:100,output_tokens:1` is accepted as non-error, zero denials and one output token. This is ambiguity inside a single event, separate from the event-order issue above. Reject duplicates recursively with a strict visitor before interpreting type/status/counters; the first adapter's `codex.rs:573-629` already does this. Add top-level and nested negative fixtures.

### R4 — P1: preserve malformed usage and parent/child provenance instead of falling back

**Location:** `crates/admiralty-runtime/src/providers/claude.rs:229-251`, `:258-279`.

An assistant record with input/output 1/2 followed by a terminal usage record with input 100 and invalid output -1 is accepted as usage 1/2: malformed terminal usage becomes None and `.or(message_usage)` silently substitutes older counters. In addition, `usage:null`, a number, or a string is treated as a usage-bearing event with all categories None because the parser never requires an object. Forwarded opaque child messages can replace parent message usage when the terminal result lacks usage (parent 100/10, child 1/1 yields 1/1), despite the unconditional parent/child-deduplication qualification.

Distinguish absent, valid partial, malformed and scope-unknown usage. Reject malformed supplied counters/objects; keep missing categories unknown; track main/child inclusion explicitly and never select an opaque child's counters as the authoritative parent turn total. Normalize through the existing usage model with stable turn/source identity or keep native overlap unqualified. Retain raw evidence and coverage instead of silently lowering apparent spend. These examples do not assert that unknown categories are currently zeroed: the bug is invalid/provenance-losing fallback.

### R5 — P2: permit normal multiline task capsules

**Location:** `crates/admiralty-runtime/src/providers/claude.rs:118-124`.

`char::is_control` rejects LF, CR and tab before JSON encoding. A normal task capsule containing goal, write scope and deny scope on separate lines is therefore rejected; the candidate test currently asserts that LF must fail. JSON encoding can represent these characters safely inside one JSONL frame. Allow supported whitespace, reject forbidden bytes such as NUL, and apply a bound to the encoded envelope before allocating/emitting it, as the first adapter does for its prompt.

The accepted 65,536-quote prompt encoded to 131,127 bytes in the probe. That is an encoded-budget/integration observation, **not** a claim of unbounded memory: the raw 64 KiB limit still provides a finite upper bound and the result is below MAX_EVENT_BYTES. Define and test the actual outgoing-frame budget when connecting this encoder to shared input admission.

### R6 — P2: do not accept a permission flag excluded by captured CLI help

**Location:** `crates/admiralty-runtime/src/providers/claude.rs:65-69`, `:94-95`.

Validation accepts `permission_mode="default"` and emits `--permission-mode default`, but the candidate's own 2.1.302 help lists only acceptEdits, auto, bypassPermissions, manual, dontAsk and plan at `tests/fixtures/providers/claude/claude-2.1.302-help.txt:150-153`. A default value reported by an init fixture is not evidence that this CLI flag accepts that spelling. Use a version-qualified typed subset of actual launch choices; if “default” means omit the option, encode omission explicitly and bind the resulting observed mode.
